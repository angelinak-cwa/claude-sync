# ccsync: Claude Code и Orca на всех своих компьютерах

Плагин синхронизирует между вашими компьютерами то, что Claude Code и Orca хранят только локально:

- **чаты** — незакрытый чат продолжается на другом компьютере с полным контекстом;
- **память** (`memory/*.md`, то, что Claude «запомнил» про проект);
- **правила**: `~/.claude/CLAUDE.md`, `rules/`, личные `skills/`, `commands/`, `agents/`, а также `CLAUDE.md` и `.claude/` каждого проекта;
- **мелкие файлы проектов** и workspaces Orca (до 5 МБ, без `.git`, секретов и `*.local.*`);
- **структуру Orca**: проекты и workspaces, созданные на одном компьютере, сами появляются на другом;
- **открытые вкладки**: чаты, открытые в Orca на одном компьютере, сами открываются на другом.

Работает в Claude Code (терминал, десктоп-приложение, VS Code) и в Orca: Orca запускает тот же Claude Code. Часть про Orca (структура и вкладки) работает на Windows, когда Orca запущена.

## Как устроено

- Данные лежат в **вашем личном приватном** git-репозитории (например, `claude-data`). Он отдельный от репозитория с плагином.
- При старте сессии плагин скачивает изменения, создаёт недостающие проекты/workspaces и открывает вкладки с чатами другого компьютера.
- Перед каждым вашим сообщением плагин проверяет, не дописан ли этот чат на другом компьютере. Если дописан — сообщение не отправляется, вкладка закрывается и чат открывается заново в свежей версии; повторите сообщение там.
- После каждого ответа Claude и при закрытии сессии плагин отправляет ваши изменения.
- Пути считаются относительно домашней папки: `C:\Users\anna\orca\projects\x` и `C:\Users\anna.k\orca\projects\x` — один проект. Поэтому проекты и workspaces должны лежать по одинаковым путям (в Orca: `~/orca/projects/<проект>`, `~/orca/workspaces/<проект>/<workspace>`). Называйте их латиницей.

## 1. Что нужно на компьютере

- **Claude Code**, **Git** (на Windows это Git for Windows, он уже стоит, если работает Claude Code), для части про Orca — **Orca**.
- Пустой **приватный** репозиторий для данных, например `claude-data` в своём личном аккаунте GitHub/Bitbucket.

## 2. Установка (один раз на каждом компьютере)

```bash
claude plugin marketplace add <ссылка на репозиторий с плагином>
claude plugin install ccsync@comrade-sync
```

Затем в Claude Code: `/plugin` → Marketplaces → comrade-sync → **Enable auto-update**.

Перезапустите Claude Code и выполните:

```
/ccsync:setup https://github.com/<аккаунт>/claude-data.git
```

Если откроется окно входа, войдите. На втором компьютере сделайте то же самое **с той же ссылкой**. Правила и файлы при самом первом подключении берутся из репозитория, а местные версии сохраняются в `~/.claude-sync-data/conflicts/`.

## 3. Команды

| Команда | Что делает |
| --- | --- |
| `/ccsync:setup <ссылка>` | подключить репозиторий с данными |
| `/ccsync:now` | синхронизировать прямо сейчас |
| `/ccsync:status` | что настроено, когда синхронизировалось, что сделано в Orca |
| `/ccsync:tabs` | открыть проекты, workspaces и вкладки другого компьютера, не дожидаясь новой сессии |

## 4. Как это ведёт себя

- **Уходить можно без действий**: изменения уходят после каждого ответа.
- **Один чат на двух компьютерах**: продолжайте где удобно. Если вкладка с чатом осталась открытой на другом компьютере, при следующем сообщении там плагин сам переоткроет чат в свежей версии.
- **`/clear`**: на другом компьютере вкладка со старым чатом заменяется новым чатом.
- **Если чат дописали на двух компьютерах одновременно**, остаётся более длинная версия, вторая сохраняется в `~/.claude-sync-data/conflicts/`.
- **Память и правила, изменённые на двух компьютерах сразу**: `MEMORY.md` склеивается, для остальных файлов остаётся версия текущего компьютера, вторая — в `conflicts/`.
- **Удаление**: удалённый чат на другом компьютере не удаляется. Удалённый проект или workspace на другом компьютере не удаляется и здесь не создаётся заново; `/ccsync:status` покажет, что убрать вручную.
- **Новый проект с другого компьютера**: при первом открытии Claude спросит, доверяете ли вы папке. Выберите «Yes, I trust this folder» (один раз на проект; workspaces внутри доверенного проекта не спрашивают).
- **Старые папки**: в репозитории с данными в `structure/aliases.tsv` можно указать «старый путь<TAB>новый путь» (или `-`, чтобы папку не переносить). Чаты старой папки копируются в новую, и она не создаётся на других компьютерах.
- **В чатах бывают данные клиентов и ответы сервисов.** Репозиторий с данными должен быть приватным и только вашим.

## 5. Настройки (необязательно)

В `~/.claude/settings.json`, блок `"env"`:

| Переменная | По умолчанию | Что значит |
| --- | --- | --- |
| `CCSYNC_INTERVAL` | `0` | не чаще чем раз в N секунд отправлять изменения после ответов (0 — после каждого) |
| `CCSYNC_DIR` | `~/.claude-sync-data` | где лежит локальная копия репозитория с данными |
| `CCSYNC_NO_ORCA` | `0` | `1`: не трогать Orca (без структуры и вкладок) |
| `CCSYNC_DISABLE` | `0` | `1`: временно выключить |

## Ограничения

- Не синхронизируется `~/.claude/settings.json`: там пути и секреты конкретного компьютера.
- Скиллы организации из claude.ai (`~/.claude/skills/synced`) Claude синхронизирует сам, плагин их не трогает.
- Если интернета нет или Orca закрыта, плагин ничего не ломает: синхронизирует при следующей возможности. Что не получилось в Orca, видно в `/ccsync:status`.
